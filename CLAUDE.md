# CLAUDE.md — working rules for this repository

KyrgyzSTEM: olympiad-preparation platform for high-school students (minors) in
Kyrgyzstan. Monorepo: `apps/api` (FastAPI) and `apps/web` (Next.js). Read
`docs/ARCHITECTURE.md`, `docs/API_CONTRACT.md`, `docs/SECURITY.md` and
`docs/ROADMAP.md` before non-trivial work.

## Commands

API (`apps/api`, uses uv):
- `uv run ruff format . && uv run ruff check .`
- `uv run mypy app scripts tests` (strict)
- `TEST_DATABASE_URL=postgresql+psycopg://...  uv run pytest` — real PostgreSQL, database is wiped
- `uv run alembic revision --autogenerate -m "msg"` / `uv run alembic upgrade head`
- `uv run python -m scripts.export_openapi` — regenerate the contract after API changes
- `uv run python -m scripts.seed` — synthetic dev data (needs `SEED_PASSWORD`)
- `uv run python -m scripts.purge_retention` — delete attendance past `ATTENDANCE_RETENTION_DAYS`
- `uv run python -m scripts.import_content --author-email EMAIL | --author-unlinked [slug ...]` —
  verify + import `content/` (as `in_review`). One option is required: link the author's account
  whenever the author is known; `--author-unlinked` means reviewers must attest instead, which is
  audited but not proof of identity (audit F-05, mitigated, not closed)
- `uv run pytest tests/test_content.py` — problem checks; set `KS_CXX` or install g++ for C++
- `uv run python -m scripts.run_ai_eval --provider fake|configured` — assistant eval (configured costs money)
- `uv run python -m scripts.promote_admin EMAIL` — first admin of a deployment (audited; no default admins)
- `uv export --locked --format requirements-txt --no-emit-project > req.txt && uvx pip-audit --strict --disable-pip --require-hashes -r req.txt`

Web (`apps/web`):
- `npm run gen:api` (after exporting OpenAPI), `npm run lint`, `npm run typecheck`,
  `npm test`, `npm run build`, `npm run e2e` (full stack required)
- `npm audit --audit-level=high`

Stack and deployment (docs/DEVELOPMENT.md, docs/DEPLOYMENT.md, docs/OPERATIONS.md):
- `docker compose up --build --wait` — dev stack (db, api, web); not run yet on any machine
- `deploy/docker-compose.prod.yml` + `deploy/Caddyfile` — staging/production; `deploy/smoke-test.sh`,
  `deploy/backup.sh`, `deploy/restore.sh`
- CI: `.github/workflows/ci.yml` (api, web, contract drift, e2e, proxy-smoke), `audit.yml` (weekly)

## Non-negotiables

- **Never execute submitted code** in the web or API process. Judging goes through the
  `JudgeClient` interface to an isolated Judge0 (Phase 3).
- Authorization is enforced **server-side** in FastAPI dependencies/services. The UI's
  role checks are cosmetic.
- Every unsafe authenticated request passes CSRF (`get_current_session` does this
  automatically — do not bypass it).
- Request models extend `RequestModel` (`extra="forbid"`); responses use explicit
  schemas, never ORM objects. Never serialize `password_hash`, tokens or IPs.
- Schema changes need an Alembic migration; `tests/test_meta.py` fails on model/migration drift.
- Keep `openapi.json`, `schema.d.ts` and `docs/API_CONTRACT.md` in sync with the code.
- Sensitive admin actions call `audit.record(...)` in the same transaction.
- No new personal-data fields without updating `docs/SECURITY.md` first.
- Seed/demo data is synthetic: `is_synthetic=True`, `@example.com`, `[Synthetic]` prefix.
  Never invent real people, schools, results, testimonials or metrics.
- Problems/editorials must be original or have verified licenses; keep attribution
  (`docs/CONTENT_GUIDE.md`). Never publish a problem yourself or mark AI-drafted content
  as reviewed: publishing is a human reviewer's decision.
- Content Python (`content/**/*.py`) is executed by the importer/tests: review it as code.
- CHECK constraints are not autogenerated by Alembic: add them to the migration by hand
  (`tests/test_meta.py` compares them).
- Secrets only via environment variables. Commit `.env.example`, never `.env`.
- Logs are structured (`app/core/logs.py`): never log bodies, query strings, cookies, tokens,
  IPs, emails or user ids; the request log uses the route template. `tests/test_ops.py` checks it.
- Production keeps a reverse proxy that overwrites `X-Forwarded-For`, and the API trusts it only
  from the web container (audit F-01). Never `FORWARDED_ALLOW_IPS=*`; one API worker.
  With the web app on Vercel, the API trusts it only from the secret-checking gateway
  (`deploy/docker-compose.gateway.yml`, docs/DEPLOYMENT.md); never weaken those checks.
  With the API itself on Vercel (experiment), `CLIENT_IP_SOURCE=vercel` reads Vercel's
  overwritten `x-forwarded-for` only when `VERCEL=1`, and `RATE_LIMIT_BACKEND=postgres` is
  required; keep both checks in `app/core/config.py`.
- Never commit database dumps; staging uses synthetic data, never a copy of production.
- `olympiad` must not import from `orgs`; `core` imports nothing from `modules`.
- UI: every data view handles loading, empty, error, unauthorized and success states;
  all strings go through `t()` with keys present in `en.ts`, `ru.ts`, `ky.ts`.
- Prefer the simplest thing that works; no new dependencies without a reason.

## Definition of done

Acceptance criteria in `docs/ROADMAP.md` met · integrated into the running app ·
migrations included · authorization and validation tested · lint/type/test/build run
and failures reported exactly · UI states handled · docs updated to match reality.

## Conventions

- Error envelope `{"error": {"code", "message", "details"}}`; raise `ApiError`.
- Routes live under `/api/v1`; modules expose `router.py`, `service.py`, `models.py`, `schemas.py`.
- Tests: use the `signed_in(Role.x)` / `make_user` / `make_problem` fixtures; cover
  anonymous (401), wrong role (403), another user's data (404/empty) and the happy path.
- Per-user idempotent writes use `_insert_once` (`ON CONFLICT DO NOTHING`).
- AI assistant: never claim accuracy without the human-reviewed eval set; never store prompt
  or answer text; a fake model may exist only in `tests/` or as the labelled eval harness.
